# crosstab-analyst · 用户研究交叉表分析师

一个可长期复用的**消费者研究 / 市场调研交叉表分析 Skill**（Claude Code Skill）。上传任意行业、任意问卷结构的交叉表数据，它会自动识别数据结构，找出不同细分用户群体之间的行为与需求差异，提炼消费者洞察，并转化为业务建议。

**不需要你懂统计，也不需要写公式——你只需要给数据、说需求。**

---

## 这是什么

「交叉表」是调研里最常见的表格形式：**题目 × 细分人群 × 百分比/频数**。传统做法是人工一题一题对着看，效率低且容易漏掉关键差异。

这个 Skill 把资深消费者研究分析师的工作方法固化下来，自动帮你：

1. 看懂交叉表的结构（题目、选项、细分维度、样本量、百分比分母）
2. 先全表扫描建立「数据地图」，再决定重点分析什么（而不是逐题机械罗列）
3. 找出**不同用户群体之间最有价值的差异**
4. 跨题目整合，构建完整用户画像
5. **主动寻找反面证据**，避免确认偏误（不只听你想听的）
6. 严格标注小样本（Base N < 30）等数据可靠性风险
7. 区分「数据发现 / 消费者洞察 / 业务建议」三个层次，不强行给结论

## 🚀 小白操作指南（3 分钟上手）

### 第 1 步：安装

> 前置条件：已安装 [Claude Code](https://claude.com/claude-code)（CLI、VSCode 插件或桌面 App 均可）。

**方式一：个人 Skill（推荐，所有项目通用）**

```bash
git clone https://github.com/Raylei21/crosstab-analyst.git ~/.claude/skills/crosstab-analyst
```

**方式二：项目 Skill（只对当前项目生效）**

```bash
git clone https://github.com/Raylei21/crosstab-analyst.git .claude/skills/crosstab-analyst
```

> 装完如果 `/crosstab-analyst` 没出现，重启一下 Claude Code 或新开一个会话即可。

### 第 2 步：启动它（两种方式，任选其一）

**方式 A：直接说人话（推荐，不用记命令）**

只要在对话框里说类似的话，就会自动触发：

- 「帮我分析这份交叉表」
- 「比较一下不同用户群体的差异」
- 「提炼这份调研数据的消费者洞察」
- 「高价值用户画像是什么样的」

**方式 B：用斜杠命令**

输入 `/crosstab-analyst`（或输入 `/` 后在列表里点选）。

### 第 3 步：给它数据

- 把 **Excel / CSV** 文件拖进对话框（最准）
- 或直接**粘贴表格内容**
- 或发**截图**（能读，但数字密集时容易看错，优先用文件）

### 第 4 步：看它自动输出

它会自动按这个顺序给你一份报告：

> 数据结构与样本量 → 数据质量检查 → 整体用户主要发现 → 最值得关注的群体差异 → 核心消费者洞察 → 反面证据检查 → 业务启发 → 值得进一步研究的问题

### 第 5 步：拿到结果后继续追问

结果出来只是开始，可以随时接着问：

| 你想干嘛 | 就这么说 |
|---|---|
| 深挖某个群体 | 「深入分析一下高价值用户」 |
| 比较两个群体 | 「对比一下 18-24 岁和 25-34 岁的差异」 |
| 只看某道题 | 「第 5 题各个群体表现如何」 |
| 验证一个想法 | 「业务假设是高价值用户更看重会员权益，数据支持吗？帮我同时找反面证据」 |
| 要汇报材料 | 「把核心发现整理成给管理层看的 Top Insights」 |

## 常见问题 FAQ

**Q1：输入 `/crosstab-analyst` 没反应？**
刚装好的 Skill 可能当前会话还没加载。重启 Claude Code 或新开一个会话即可。

**Q2：只有截图/图片，能分析吗？**
能读，但图片里的数字和百分比容易看错，尤其交叉表数字密集。有 Excel/CSV 时优先用文件。

**Q3：为什么它不罗列所有数据？**
设计如此。这个 Skill 只挑「最有价值的发现」，而不是把每道题念一遍。想看全量，就说「给我完整逐题分析」。

**Q4：它会自己编数据吗？**
不会。它的铁律之一是「不虚构任何数字」，并且会主动找反面证据、标注小样本风险，避免过度解读。

**Q5：数据会泄露吗？**
数据会发送给模型服务方处理。如果是公司敏感的用户数据，上传前请先确认合规要求。

## 设计原则

- **Data First / Evidence-based**：所有结论以实际数据为基础，关键洞察必须附具体数据（Base N、Count、百分比）。
- **通用性**：不绑定任何品牌、行业或固定细分维度。
- **No Fabrication / No Causal Overclaim**：不虚构数据，不把相关当因果。
- **Transparency**：数据不完整或分母无法确定时明确说明，不猜测。
- **主动质疑**：对关键结论强制做反面证据检查，避免确认偏误。
